## 1. Classification Taxonomy and Non-Conflation Rule

Every acceptance-matrix row (`TA-01`..`TA-30`, `TA-M0`), work packet (`WP-00`..`WP-24`, `WP-M0`), external gate (`EXT-01`..`EXT-09`), open GitHub Issue (`#3`, `#4`, `#5`, `#17`), and open pull request (`PR #43`) is classified below using six mutually explicit states:

- `COMPLETE_VERIFIED` — Objective acceptance criteria for the authorized scope are met, tested, reviewed, and verified (`caab864ee2ea0520f922c4646a883b38e0ac02e7` + PR #98).
- `ENGINEERING_ACTIONABLE` — Authorized engineering work remains that can close all or part of this item **without** new founder, legal, clinical, or signing approvals (`0` items remaining after PR #97 + PR #98).
- `REQUIRES_SOURCE_ADMISSION` — Blocked specifically on a signed `VERIFIED_ALLOWED` source, dataset, or model-weight admission decision on [Issue #5](https://github.com/TheHalfMoon/SafeEvidence/issues/5).
- `REQUIRES_FOUNDER_DECISION` — Blocked on an accountable founder governance, phase-ownership, private-publication, or release-custody decision.
- `REQUIRES_INDEPENDENT_EXPERT` — Blocked on an authenticated, independent human technical or security review (never satisfied by an AI review).
- `REQUIRES_REGULATORY_OR_CLINICAL_EVIDENCE` — Blocked on the signed clinical intended-use and evaluation charter, clinician-adjudicated holdouts, or regulatory determination ([Issue #4](https://github.com/TheHalfMoon/SafeEvidence/issues/4)).

**Audit rule enforced throughout:** whenever an item combines an actionable engineering sub-task with an external gate, the actionable sub-task is split out as `ENGINEERING_ACTIONABLE` rather than hidden behind the external blocker.
